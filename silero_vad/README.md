# Silero VAD 面试详解

## 1. 模型概况

| 项 | 说明 |
|---|---|
| 出处 | snakers4/silero-vad（GitHub 开源，v5 为当前版） |
| 任务 | 语音活动检测 VAD：逐帧输出"是语音"概率 0~1 |
| 规模 | **~1.8M 参数 / 2MB（JIT）/ 1.7MB（ONNX）**——本工程最小的模型 |
| 输入 | 16k 采样率、512 样本（32ms）定长帧流 |
| 输出 | 当前帧语音概率 + 隐藏状态（有状态流式） |
| 应用 | ASR 前置切片、实时通话静音抑制、音频事件触发、节省 ASR 算力 |

**为什么它经典**：极致轻量 + CPU 单帧 <1ms + 免特征工程（直接吃原始波形），是"小模型解决被高估问题"的代表案例。

## 2. 架构原理

```
原始波形帧(512) → [Conv1d × N + ReLU] → [GRU × 2] → FC → sigmoid 概率
                     ↑ 提取局部频谱模式    ↑ 时序记忆(状态跨帧传递)
```

- **不用手工特征**：不提 mel/fbank，卷积直接从波形学滤波器组（等效可学习的 filterbank）
- **有状态设计**：GRU hidden state 每帧传入传出（`reset_states()` 清零），支持无限长流式推理
- **训练目标**：帧级二分类交叉熵；标签来自带静音标注的大规模语料
- **窗口选择 32ms**：兼顾响应延迟与音素完整性；官方还有 1536 样本（96ms）模式，越长越准越慢

v4 vs v5：v5 支持可变采样率（8k/16k/24k/48k）via 重采样层，且 ONNX 接口带显式 state 张量输入。

## 3. 训练过程（自训替代：`train_custom_vad.py`）

什么时候需要自训 VAD？——业务域特殊（呼吸声/咳嗽/键盘声判定标准与通用模型不同），或要嵌入更小的定制结构。

本工程实现流程：
1. **特征**：40 维 log-mel（帧长 400、hop 160 = 10ms 帧移）
2. **数据**：`speech/` 与 `noise/` 两类 wav 目录；帧级标签：语音文件全标 1，噪声全标 0（生产中用能量+对齐做弱标注）
3. **模型**：4 层 1D-CNN（~100K 参数，比 Silero 更小），感受野覆盖 ±20 帧
4. **损失**：逐帧 BCEWithLogits
5. **推理**：滑窗逐帧概率 → 阈值(0.5) → 二值序列 → 合并成 [start, end] 时间戳（`infer.py:get_timestamps`）

**生产级改进方向**：加迟滞阈值（进入 0.6 / 退出 0.4 防抖动）、最小段长度过滤、hangover 平滑。

## 4. 参数调整

| 参数 | 默认 | 调整建议 |
|---|---|---|
| threshold | 0.5 | 高噪声场景升到 0.6~0.7 降误检；漏检敏感（如字幕）降到 0.35 |
| min_speech_duration | 250ms | 过滤呼吸/短噪声；ASR 切片可放宽到 100ms |
| min_silence_duration | 100ms | 决定切段灵敏度；实时字幕建议 300~500ms 防止频繁闪烁 |
| speech_pad_ms | 30ms | 段边界向外扩，防止切掉爆破音声母 |
| 窗口 | 512@16k | 24k/48k 场景按官方对应窗长 |

**评估指标**：帧级 F1 / recall 优先（漏检直接导致 ASR 丢内容，误检只是浪费算力），再做段级 IoU。

## 5. 训练速度优化

- 小模型瓶颈在**数据 IO**而非计算：用 `soundfile` 分块读 + 预提取特征缓存
- 合并变长音频成定长 batch（pad + mask）
- AMP 对 100K 模型无必要，CPU 训练即可（这正是小模型的优势）

## 6. 推理优化（本工程 `optimize.py`）

| 手段 | 效果 |
|---|---|
| **ONNX Runtime**（官方提供 onnx） | CPU 提速 20~50%，延迟更稳（无 GIL/调度抖动） |
| **批处理多路音频** | 客服/会议场景 8 路并发拼 batch，吞吐近线性 |
| **帧内流水线** | 推理与音频采集双线程，VAD 延迟被采集掩盖 |
| **量化** | 收益有限（模型已 2MB、GRU 量化后掉点明显），面试时说明"不盲目量化"反而加分 |

注意 ONNX 有状态接口：`input [B,512] + state [2,B,128] + sr`，每次 forward 返回新 state，多路会话各持独立 state。

## 7. 面试 Q&A

**Q1: 为什么用 VAD 而不是能量阈值？**
A: 能量阈值在噪声环境（咖啡馆、风声）失效；VAD 学的是"人声特征"而非能量大小。能量法只适合信噪比极高的桌面静音检测。

**Q2: VAD 在 ASR 系统里怎么部署？**
A: 流式：环形缓冲区 → 每帧过 VAD → 累计静音 > 阈值则切段送 ASR，同时降低 ASR 调用量 50~80%（纯静音/噪声段不推理）。

**Q3: 流式推理如何管理状态？**
A: GRU hidden state 是跨帧上下文，按会话持有；切换说话人/重置场景时 `reset_states()`，否则历史状态污染判定。

**Q4: VAD 误判的代价如何权衡？**
A: 不对称：漏检（丢语音）> 误检（多算一段）。所以阈值偏保守（低 recall 高 precision 取舍反转——宁可多触发）。可用 PR 曲线按业务代价选阈值，而不是死守 0.5。

**Q5: 为什么 Silero 不用 Transformer？**
A: 32ms 窗帧级任务延迟敏感、模型要部署到浏览器/嵌入式；GRU+CNN 在 <2M 参数下已够用——架构选择跟着部署约束走，这是工程判断力的体现。
