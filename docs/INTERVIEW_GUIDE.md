# 六类模型面试知识体系

这份文档不是背诵答案列表，而是一套回答结构。推荐每个问题都按“业务目标 → 模型机制 → 指标 → 优化 → 风险”展开。

## 1. 先准备一条完整项目叙事

一个合格的项目介绍应在两分钟内回答：

1. 解决什么问题，输入输出和业务约束是什么？
2. 为什么选这个模型，而不是更大的模型或传统算法？
3. 数据怎么构造，如何划分，最容易发生什么泄漏？
4. 用什么指标，为什么该指标匹配业务成本？
5. 做了什么优化，基线和优化方案是否公平比较？
6. 遇到什么失败，最后如何验证没有回归？

示例叙事：

> 我实现了一条本地长音频转写流水线。Silero VAD 以 32ms 窗口过滤静音并切段，Whisper tiny 在 MPS 上做浮点解码，同时比较 CPU 动态 int8。评价不仅看单段延迟，还看整段实时率和 WER。VAD 阈值降低会提高语音召回，但也会增加 Whisper 计算量，因此最终按“漏字成本高于多算一段”的业务权重联合调参。量化模型用相同音频和解码长度测试，并检查转写文本，而不是只比较模型文件大小。

这段话包含系统设计、指标权衡和实验方法，比“调用了两个开源模型”更有区分度。

## 2. Whisper

### 架构与训练目标

Whisper 是 Encoder–Decoder Transformer：音频先变为 log-Mel，Encoder 建模声学上下文，Decoder 自回归预测 token。它不是 CTC；训练采用 teacher forcing 的 token 交叉熵。语言、转写/翻译任务和时间戳都统一编码为特殊 token。

与 CTC 的关键区别：

- CTC 依赖单调对齐和条件独立近似，解码并行性更好。
- Seq2seq Decoder 自带语言建模能力，能统一翻译与时间戳，但自回归更慢，也可能产生幻觉。
- Whisper 的 30 秒窗口是训练分块约定；长音频仍要滑窗或 VAD 切片。

### 微调怎么讲

- 声学域差异小、文本术语差异大：先冻结 Encoder，训练 Decoder。
- 噪声、口音、麦克风差异大：Decoder 收敛后再用更小学习率解冻 Encoder。
- batch 受限：梯度累积改变优化器更新频率，但不会减少单样本激活。
- gradient checkpointing 不保存部分中间激活，反向时重算，以时间换内存。
- 中文评估更常用 CER；英文常用 WER。计算前必须统一大小写、标点、数字和空格规则。

### 优化追问

动态量化主要处理 Linear。Transformer 中 FFN 和 attention projection 的 Linear 权重占比高，因此模型大小通常明显下降；但自回归解码包含 Python/生成循环、KV cache 和小矩阵计算，端到端延迟不一定按权重大小同比下降。

`torch.compile` 对固定 shape 的整图收益更容易稳定；自回归生成会因动态长度、缓存结构和控制流产生 graph break。应分别记录首次编译时间和稳态延迟。

### 高频问题

**为什么会幻觉？** Decoder 具有语言模型先验；输入静音、噪声或切段上下文不足时，语言先验可能压过声学证据。用 VAD、no-speech 概率、重复/压缩比检测、温度回退和上下文控制缓解。

**长音频边界怎么处理？** 切片保留少量重叠，使用时间戳对齐，在重叠区按 token 时间或文本相似度去重。VAD 段两端应 padding，避免截掉爆破音。

**为什么量化后不能只看文本相同？** 单个样本一致不能代表 WER；还要覆盖口音、噪声和长尾词，并检查量化是否改变置信度或时间戳。

## 3. Silero VAD

### 问题本质

VAD 是带时序约束的帧级二分类。单帧概率不是最终产品，还要经过迟滞阈值、最短语音、最短静音和边界 padding，才能得到稳定语音段。

迟滞阈值使用较高阈值进入语音、较低阈值退出语音，可避免概率在 0.5 附近抖动。`min_silence_duration` 是 hangover 的一种实现：短暂停顿仍属于当前语音段。

### 指标与业务成本

- 帧级 precision/recall/F1：衡量逐帧判断。
- 段级召回：一句话是否被完整保留。
- onset/offset 延迟：流式系统何时开始或结束触发。
- 下游成本：送入 ASR 的音频比例和最终 WER。

字幕场景通常更怕漏检，因此降低进入阈值或增加边界 padding；唤醒/计费场景可能更怕误触发。

### 自定义 VAD 的局限

本工程轻量 CNN 是教学基线。纯语音文件全 1、纯噪声全 0 不能覆盖真实混合场景；生产数据应含语音与噪声混合、边界标签、困难负例，并按会话划分训练集和验证集，避免同一录音切片泄漏。

## 4. ECAPA-TDNN

### 四个核心组件

1. TDNN/空洞一维卷积扩大时间感受野。
2. Res2Net 风格通道分组提供多尺度特征。
3. SE 通道注意力根据全局上下文重标定通道。
4. Attentive Statistics Pooling 对时间帧加权，并拼接均值与标准差得到句级表示。

### 为什么用 AAM-Softmax

普通交叉熵只要求类别可分，没有明确约束 embedding 的类内和类间几何。AAM 将特征和分类权重归一化，对正类角度加 margin：

```text
cos(theta_y + m) * s
```

`m` 控制角间隔，`s` 把 [-1,1] 的余弦范围放大到适合 softmax 的 logit 尺度。标准实现还需处理角度越过 pi 后的单调性；本工程使用不显式计算 `acos` 的等价公式和单调修正。

### 验证与分类的区别

- 闭集分类：测试身份必须在训练类别中，输出类别概率。
- 开集验证：判断两段音频是否同一人，测试人可以从未出现在训练中。
- 训练时 AAM 分类头帮助塑造 embedding；推理验证时丢弃分类头，只比较归一化 embedding。

阈值必须在目标域验证对上标定。常见指标是 EER、minDCF、ROC，以及固定 FAR 下的 TAR。一个固定的“0.75 阈值”只能作为演示，不能跨数据集复用。

### 冻结骨干为什么要缓存 embedding

骨干不更新时，同一音频每个 epoch 的 embedding 完全相同。预计算一次能把后续训练变成小型 MLP/AAM 训练。这是算法理解带来的系统优化，不是低层算子优化。

## 5. MobileNetV3

### 从 V1 到 V3

- V1：depthwise convolution 做空间滤波，pointwise 1×1 做通道混合。
- V2：倒残差和线性瓶颈；先扩张再 depthwise，投影回低维时不用 ReLU，减少信息损失。
- V3：NAS 搜索、SE、h-swish 和尾部结构调整，优化目标直接包含设备延迟。

Depthwise convolution 的 FLOPs 很低，但算术强度也低，容易受内存带宽限制。因此 FLOPs 降低不等于所有硬件上延迟同比下降。

### 迁移学习细节

加载 ImageNet 权重后，输入必须采用对应归一化。冻结参数还不够：BatchNorm 的 running statistics 仍会在 train 模式更新，所以冻结骨干时应让骨干保持 eval。

小数据先训分类头，再逐步解冻；解冻后通常降低学习率。应保留独立验证集，而不是用训练准确率判断模型是否有效。

### PTQ 三步

1. 融合 Conv/BN/Activation，减少量化边界和运行时算子。
2. `prepare` 插入 observer，用校准数据统计激活范围。
3. `convert` 把 observer 和浮点算子转换为量化算子。

动态量化只覆盖 Linear，对 MobileNet 的卷积主干帮助很小；静态 PTQ 才是主要路线。量化友好不仅取决于模型参数量，还取决于算子支持、激活分布和每通道量化。

## 6. YOLO11n

### 检测流水线

```text
letterbox → backbone → 多尺度 neck → 解耦检测头 → bbox 解码 → NMS
```

多尺度特征让高分辨率层负责小目标、低分辨率层负责大目标。解耦头分开分类和回归，减少两种目标对特征的冲突。DFL 将边界距离表示为离散分布，再取期望获得连续坐标。

### 指标

- precision/recall 受置信度阈值影响。
- AP 是一条 PR 曲线下面积。
- mAP@0.5 较宽松；mAP@0.5:0.95 平均多个 IoU 阈值，更强调定位质量。
- 部署还应按目标尺寸报告 AP_small/AP_medium/AP_large，并检查每类别结果。

### 公平 benchmark

不能把 `model.predict(image_path)` 与 ONNX 的随机张量裸前向直接比较：前者包含图片读取、letterbox、模型、解码和 NMS，后者只有模型。要么两边都测模型核，要么两边都测端到端。本工程优化脚本选择端到端边界，并打印检测结果摘要。

### ONNX 量化

卷积网络更适合静态 PTQ。QDQ 格式显式插入 QuantizeLinear/DequantizeLinear，方便运行时做图优化。动态量化主要面向 MatMul/Gemm，盲目量化卷积可能生成当前 CPU provider 不支持或更慢的图。

量化后必须在验证集重跑 mAP。单张 bus 图只能检查模型仍能输出合理框。

## 7. SCRFD + ArcFace

### 四段式系统

1. SCRFD 输出 bbox 和五点关键点。
2. 五点相似变换将脸对齐到 112×112 模板。
3. ArcFace 骨干输出 L2 归一化 embedding。
4. 1:1 用余弦阈值，1:N 用向量索引召回后精排。

### 为什么必须是相似变换

相似变换只允许旋转、统一缩放和平移，能够校正姿态又尽量保留人脸几何。普通六自由度仿射还允许剪切和非等比缩放，可能扭曲身份特征。本工程用 OpenCV `estimateAffinePartial2D` 求相似变换，并用标准模板点做回归测试。

### ArcFace、CosFace、SphereFace

- SphereFace：`cos(m * theta)`，乘性角间隔，优化较难。
- CosFace：`cos(theta) - m`，余弦空间加性间隔。
- ArcFace：`cos(theta + m)`，角度空间加性间隔，几何解释直接。

ArcFace 的 margin 只在训练分类头中使用；推理输出 embedding 时不需要分类头。

### 阈值和安全

人脸识别不是活体检测。照片、屏幕重放和面具攻击需要独立风控层。阈值应按注册、解锁、支付等不同业务的 FAR 预算分别标定，并保留低质量拒识机制。

1:N 场景必须考虑库规模效应：候选越多，出现高相似度偶然近邻的概率越高，因此 1:1 阈值不能直接照搬到百万库检索。

### PTQ 验证

同输入的 fp32/int8 embedding cosine 接近 1 只能证明数值变化较小。正式验收要重新计算 ROC、EER、TAR@FAR，并检查阈值是否漂移。检测器量化还要验证漏脸率和关键点误差，因为对齐误差会继续放大到识别阶段。

## 8. 通用性能优化框架

面试中可以使用以下顺序，避免上来就说量化：

1. **定义目标**：latency、throughput、内存、功耗还是包体？
2. **建立正确基线**：固定数据、版本、预处理、线程和指标。
3. **Profile**：确认瓶颈在 IO、预处理、模型核、解码还是后处理。
4. **算法级**：更小模型、更小输入、蒸馏、剪枝、减少 beam。
5. **数值级**：AMP、fp16、bf16、int8、混合精度。
6. **图与运行时**：compile、ONNX、CoreML、算子融合。
7. **系统级**：batch、缓存、线程、异步流水线、请求合并。
8. **回归验证**：任务指标、长尾样本、阈值和故障降级。

一个优化如果无法说明适用硬件、输入 shape、精度代价和测量边界，就还不能称为工程结论。

## 9. 容易被追问的实验错误

- 量化 API 返回新模型，却仍 benchmark 原模型。
- 用随机输入检查分类精度或校准量化范围。
- GPU/MPS 未同步就计时。
- 只预热一个后端，另一个包含冷启动。
- 训练集和验证集来自同一原始录音/视频的相邻切片，造成泄漏。
- 使用预训练权重却忘记匹配归一化。
- 冻结参数但未冻结 BatchNorm 统计量。
- 只看模型文件大小，不看运行时是否支持量化算子。
- 只报告平均延迟，掩盖 p95 抖动。
- 用固定相似度阈值跨数据集、模型和库规模比较。

能主动指出这些问题，往往比背一个“理论加速倍数”更能体现工程能力。
